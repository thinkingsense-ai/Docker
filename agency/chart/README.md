# Agency cloud add-on (slices 1 to 4: the front end, the IT-risk data, Workspaces and grants, the workflow pod)

Installs Agency (the React UI and the thinking layer) beside the Ask app in the four stack charts. Off by default (`agency.enabled=false`); with it on, a stack gets one Deployment, two ConfigMaps and a Service.

- **No image to publish.** The layer is standard-library Python and runs on the stock `python:3.12-slim`; its code (`files/agency/*.py`, `contract.json`, `catalogue.json`) and the built UI (`files/agency/web.tgz`, unpacked by an init step) come from ConfigMaps. The same chart therefore works on AWS, OCI, GCP and Azure with no registry of our own.
- **Single source, four copies.** `agency/chart/agency.yaml` (template), `addons/thinking-layer` (code), `packs/catalogue.json` and `agency/chart/web.tgz` are copied into each chart by `scripts/sync-agency-addon.py`. Before a stack release run `scripts/sync-agency-addon.py --check`; it also fails when `web.tgz` was built from older UI sources (rebuild with `scripts/agency_bundle.py build`; needs node).
- **Public address.** Its own Service (`agency.service.type`, default LoadBalancer, port 8097) with the same cloud annotations as that cloud's Ask Service and the same `service.loadBalancerSourceRanges` (OKE: restrict in the load balancer subnet's security list, as for the Ask app). Plain HTTP unless you terminate TLS in front of it; the session cookie is HttpOnly and SameSite=Strict, with no `Secure` flag until it is served over HTTPS.
- **State.** Sessions, uploads and preferences are in memory, one replica: a restart signs everyone out.
- **Sign-in.** With the app's own business-user logins (`omnigate.appUsers`); the layer keeps no passwords. Single sign-on needs `agency.publicUrl` registered with the provider.

## Checked
- `helm template` of all four charts, five data sets each, Agency off: identical to `main` once random secrets are masked. Agency on renders on all four; `helm lint` passes.
- `agency/chart/tests/pod-smoke.sh`: the init step and the layer under the chart's security settings (uid 10001, read-only root, no capabilities) from the same files the ConfigMaps carry, beside a live stack: health, UI page, status, sign-in.

## Slice 2: the IT-risk data (`agency-risk`, a chart-only pack)
`demoDatasets: [agency-risk]` (it brings `it-risk` in; it mixes with the other packs and with all six; `all-packs` and a single `it-risk` do not gain it) deploys the all-packs way (connectors `pg` and `mdb`, tables addressed `pg.rca.events`) and adds:
- the Postgres schemas `rca` (incident cases and the link grades), `estate` (a simulated estate: systems, patches, changes, recovery tests, SharePoint and Slack landing tables) and `register` (risk taxonomy, rating scale, definitions, notification rules, the append-only register tables), seeded as files 05 to 07 of the packs seed ConfigMap on a fresh volume (nothing reseeds an existing release);
- those schemas in the federation list, 27 more approved questions (39 in all with the 12 IT-risk ones; the Watch, Exposure, Priorities, Notifications and Incident-brief screens ask them), and the embedding model, because an approved question is only answered from the bank with it (about 512 Mi more than IT risk alone);
- the app's SELECT-only account already gets SELECT on every schema at each start, so there are no grant files here.
Single sources stay in `demos/it-risk-rca`, `demos/it-risk-estate` and `demos/it-risk-register`; `scripts/sync-agency-addon.py` copies them into each chart's `files/`. `packs/test_agency_risk.py` locks the composition.

Checked: the seed files load clean in order on Postgres 16 beside the IT-risk seed; all 25 approved questions that read only Postgres run (two return no rows by design: the feed list needs the feed adapter and the register-runs list needs a workflow run); the older selections and all five single data sets render identically to `main`.
NOT checked: the seven questions that join MariaDB (they ran through the real app in the Docker sandbox, not from these charts); a cluster deploy; answer quality on a mix; the node size the extra memory needs (a default AWS node was already at 83% with Ask alone).

## Slice 3: Workspaces and grants (`agency.bootstrap`, on by default with Agency)
A post-install and post-upgrade Job (`agency/chart/agency-bootstrap.yaml`, python stdlib, never fails the release) loads one Workspace per pack in a mix, plus `all-data`, through the admin API, **only when the Server has no Workspace yet**, so it never overwrites a customer's own. It then sets what each login in `agency.bootstrap.grants` may do (see the values file), for logins the Server knows; nothing is granted unless listed. Workspaces scope by backend only (`pg`, `mdb`, `files`), so a pack on the shared Postgres still sees the other packs' schemas until the Server scopes Workspaces to schemas (Server#109). Not rendered for a single data set. `agency/chart/tests/test_bootstrap.py` runs the rendered script against a stub Server (4 tests): load when none exist, never overwrite, grants only for known logins, a refused admin login changes nothing.

## Slice 4: the workflow pod (`agency.workflows.enabled`, commercial edition only)
`agency/chart/agency-workflows.yaml` puts the Agency workflows (incident brief, vulnerability exception, risk assessment, major-incident decision; the payment exception too when the Treasury pack is in the selection) behind the app's own workflow API: one pod with a Temporal dev server, the worker and the gateway (port 8094, bearer token, only the app's pods may reach it), no approval inbox. The code is the closure of what `worker.py` and `gateway.py` import (computed by the sync script, so the list cannot go stale), in a ConfigMap on the stock python image. Write-back is a dry run; recommendations come from the rules only unless `agency.workflows.recommendations` is `model`. A pod init container creates the register's writer role, which can only INSERT (a trigger also refuses UPDATE and DELETE for everyone). The app is wired by the helper `omnigate.engineName` in `templates/_agency.tpl`: the payment add-on's output is byte-identical to `main`. The chart refuses (with a message) without `agency.enabled`, the `agency-risk` pack, a licence or `omnigate.adminApiToken`, or when the payment gateway is also on.
Checked: renders and lints on all four charts; legacy and payment add-on renders identical to `main`; `agency/chart/tests/pod-smoke-workflows.sh` 12 of 12 against the sandbox (the exact init script on a scratch register: INSERT yes, UPDATE and DELETE refused; the pod's three containers under the chart's security settings; the gateway refuses a call without its token and starts an incident-brief run).
NOT checked: a cluster; a real licence (the pod needs one to be reachable through the app; tests ran against the sandbox's emulated edition); the other three definitions through the pod; the Workspace `it-risk` must exist (the bootstrap Job loads it, or load your own).

## `scripts/verify-agency.sh <url> <user> <password>`
Checks a deployed Agency from the outside, like `verify-secure-deploy.sh`: layer and UI answer, the layer reaches the app, **the guided demo tour is off and its sign-in route closed** (it must never run on a real deployment), anonymous callers are refused, a wrong password and a request without the CSRF header are refused, the business user signs in, packs and the IT-risk approved questions are listed, one approved question is answered with rows (`VERIFY_ASK=0` skips it; `ASK_TIMEOUT` sets its wait), and workflows are reported on or off. Run against the local sandbox it passes 14 of 14 checks on a layer with the tour off and correctly fails the two tour checks on the sandbox's own layer (the tour is on there by design). Not run against a cluster.

## Not done
- **High availability.** Not wired, and not just a values change: the app is a Deployment with one replica and `Recreate`, holding one ReadWriteOnce volume for its data, and clustering finds peers through a static `host:port` seed list (`OMNIGATE_CLUSTER_SEED_NODES`). Running two replicas needs a StatefulSet (a volume per pod) or data kept elsewhere, seed addresses from a headless Service, the same `OMNIGATE_OIDC_STATE_SECRET` on every replica, zone spreading and a disruption budget, and a commercial licence to test. Decide the shape with Kumar first.
- The audit view's decision-file mount (the pod's volume is ReadWriteOnce, so the layer cannot share it; the Server's own decision route works without it).
- The table, document and image adapters, upload sharing; the feed adapter (reuse terms unread) and the audio and vision adapters (non-commercial or experimental) stay out.
- Deploy-form switches (CloudFormation, OCI Resource Manager, Azure createUiDefinition, GCP variables), the docs pages, a stack release on app 0.10.22 or newer and a real cluster deploy.
- The demo tour (`AGENCY_DEMO_TOUR`) is deliberately not wired: it signs in as named demo people and must never run on a real deployment.
